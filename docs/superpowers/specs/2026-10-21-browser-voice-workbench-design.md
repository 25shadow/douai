# 浏览器语音工作台设计（方案 A）

日期：2026-10-21
状态：方案 A 已确认，本文待用户审阅。

## 目标与边界

把当前三项参数表单重构为可选音色、可试听、可诊断、具有明确播报策略的浏览器语音工作台，并修复设置与实际播报脱节的问题。

本轮仅使用浏览器 SpeechSynthesis，不增加云 TTS、API Key、远程合成接口、模型下载、音频缓存或 OBS 独立音轨。保留项目现有 Vue 3、TypeScript、Python 配置 API 和 SQLite 持久化方式。不修改用户现有的无关工作区变更。

浏览器引擎仅代表调用方式，不承诺全部音色离线可用；工作台显示浏览器返回的本地/网络音色标记。不把其他厂商的稳定度、相似度、情绪等不可用参数映射成虚假控件。

## 现状与必须修复的问题

- `src/views/VoiceConfigView.vue` 仅包含启用、音量、语速、前缀，没有音色选择、试听和保存状态。
- `src/voice/voiceManager.ts` 每次调用都会 cancel，连续答对、点赞提示可能打断题干或答案。
- 当前 manager 不读取或应用前缀；设置只在配置页保存后写入内存，刷新应用无法保证使用 SQLite 中的设置。
- `src/game/quiz/quizStore.ts` 的全部播报共用一个无场景参数的入口，不能区分关键题干与高频互动。
- `config_server.py` 使用分散的语音列，前端配置 API 以全量覆盖方式保存项目配置。

## 用户工作流

进入语音配置时加载已保存设置与音色目录。用户筛选并选择音色，调整参数，使用草稿试听，确认后保存。试听不隐式保存，不将草稿参数应用到正式游戏播报。返回页面或刷新时恢复已保存设置。

页面采用与现有应用一致的紧凑工具界面，不添加营销说明、装饰性大图或嵌套卡片。桌面为音色列表与编辑/试听双栏；窄屏纵向排列，控件与文字不溢出。

### 页面组成

1. 页头：语音配置标题、引擎状态、未保存标记、保存按钮。保存过程中禁用重复提交，成功显示反馈；失败保留草稿和明确错误。
2. 音色区：搜索、语言筛选、收藏筛选、刷新音色列表。列表显示音色名、语言、本地/网络标记、默认标记，支持收藏与选中。空列表、加载中和不支持分别显示。
3. 参数区：总开关、音量、语速、音高、语言、默认前缀。数字与滑杆同步；自然、直播、快速提醒预设只修改 rate、pitch、volume，不擅自替换音色或场景规则。
4. 试听区：可编辑文本、通用/题目/互动样例、播放、暂停/继续、停止。显示待播数量、正在播报内容和错误；播放使用当前草稿，空文本不能播放。
5. 场景区：题目与答案、答对反馈、礼物助力、点赞助力、系统提示。每项有启用、前缀、优先级、文本长度和冷却时间。
6. 高级区：排队/打断/忙时丢弃策略、重复抑制、最大待播数、恢复默认参数。恢复只修改草稿，需保存后生效。

播放、暂停、停止、收藏、刷新等使用带可访问名称和 tooltip 的图标按钮。二元设置使用 checkbox 或 switch，参数使用滑杆与数字输入，策略使用 select 或分段选择。

## 配置模型与持久化

新增版本化 `voiceConfig`，作为新的语音配置唯一权威来源：

```typescript
type VoiceScene = 'quiz' | 'answer' | 'gift' | 'like' | 'system';
type VoiceQueueMode = 'queue' | 'interrupt' | 'drop';
interface VoiceScenePolicy {
  enabled: boolean;
  prefix: string;
  priority: number; // 0..3
  maxLength: number; // 20..1000 个 Unicode 码点
  cooldownMs: number; // 0..60000
}
interface VoiceConfig {
  version: 1;
  provider: 'browser';
  enabled: boolean;
  voiceURI: string;
  voiceName: string;
  lang: string;
  favoriteVoiceURIs: string[];
  volume: number; // 0..1，默认 0.85
  rate: number; // 0.5..2，默认 1
  pitch: number; // 0..2，默认 1
  prefix: string;
  queueMode: VoiceQueueMode; // 默认 queue
  maxQueueSize: number; // 1..50，默认 10，不含正在播放项
  dedupeWindowMs: number; // 0..60000，默认 3000
  scenes: Record<VoiceScene, VoiceScenePolicy>;
}
```

初始 lang 为 `zh-CN`，音色为空表示自动选择。场景默认全部启用、前缀为空：

| 场景 | 优先级 | 最大文本长度 | 冷却时间 |
| --- | --- | --- | --- |
| quiz | 3 | 1000 | 0 ms |
| answer | 0 | 200 | 3000 ms |
| gift | 2 | 200 | 1000 ms |
| like | 1 | 200 | 3000 ms |
| system | 3 | 300 | 0 ms |

SQLite 通过可重复执行的迁移新增 JSON 列。旧数据库没有新配置时，以旧 enabled、volume、rate、prefix 生成新配置，不丢失已保存值。读取 API 返回规范化 voiceConfig，同时返回旧字段作为兼容镜像。

新增 `PUT /api/config/voice` 只更新语音配置及旧语音列镜像，不覆盖房间、题库和 AI 设置。服务端校验类型、有限数字、范围、枚举和长度；失败返回 400 且不写入。prefix 最长 100 个码点，音色标识/名称最长 500，lang 最长 50，收藏最多 100 个，试听正文最多 1000 个码点。

原全量配置保存接口在 payload 包含 voiceConfig 时使用它；仅含旧字段且数据库已有新配置时，保留现有新配置，防止其他页面持有旧快照时覆盖语音工作台设置。旧字段兼容镜像从权威配置生成。

## 模块边界

- `src/voice/voiceConfig.ts`：类型、默认值、兼容迁移、纯函数校验、预设。无 Vue 和浏览器依赖。
- `src/voice/browserSpeech.ts`：隔离浏览器目录和播放 API，处理 voiceschanged、音色解析、错误映射；可注入替身做测试。
- `src/voice/voiceManager.ts`：公共播放入口、优先级队列、冷却与去重、暂停/恢复/停止、状态订阅。保留 `speak(text)` 的兼容入口，默认 system 场景。
- `src/voice/useVoiceWorkbench.ts`：页面草稿、加载/保存/脏状态、筛选、试听状态与生命周期清理。
- `src/views/VoiceConfigView.vue` 及必要的音色列表/场景参数组件：仅承担 UI 与交互，不直接拼接配置 API 请求或操作 speechSynthesis。
- `src/services/configApi.ts`：加载新配置与专用语音保存请求。
- `config_server.py`：SQLite 迁移、服务端校验、专用保存接口；必要时将语音规范化函数拆入独立 Python 模块。

不提前实现远程 Provider 框架；只用浏览器适配器作为队列与设备 API 的边界，为将来更换引擎保留余地。

## 播放行为

### 音色目录

初始化读取目录并订阅 voiceschanged，支持手动刷新。选择顺序为已保存 voiceURI、相同名称与语言、相同语言音色、浏览器默认音色。替代选择显示告警，不默默覆盖保存的音色标识。目录未就绪时仍可选择自动音色，不把暂时为空误报为永久不支持。释放订阅时移除事件监听。

### 入队规则

正式播报依次检查初始化成功、总开关、场景开关、非空文本、冷却和重复抑制，再组合全局前缀、场景前缀与正文。文本按码点截断到场景上限，去重键由场景与规范化正文组成；仅成功接纳的项目消耗冷却与去重窗口。

- queue：不打断当前项；待播项按优先级降序，同优先级保持先入先出。
- interrupt：新项目优先级不低于当前项时打断；否则按优先级排队。被打断项目不重播。
- drop：正在播放、暂停或已有待播项时丢弃新请求。
- 队列满：新项目优先级高于最低优先级待播项时，移除最早的最低优先级项；否则拒绝新项目。

播放出错时记录可见错误并继续下一项，不能卡住队列。每次取消增加播放代次，过期回调不得完成新项目或重启旧队列。stop 清空待播并取消当前播放；关闭总开关也执行 stop。

暂停/恢复使用同一运行时，不创建第二个浏览器播放器。试听明确停止当前播放和队列，按草稿独立播放单条；不经过总开关与场景过滤，也不修改正式配置。在试听期间收到的正式播报忽略，不在试听后回放过期消息。离开工作台时只取消仍属于本次试听的播放，不取消后来开始的正式播报。

状态至少包含 idle、speaking、paused、unsupported、error、当前文本、待播数、最后错误和音色回退提示，不将调用 speak 成功等同于设备已经发声。提供播放器超时恢复，防止底层没有 end/error 回调时永久占用队列；超时为当前文本长度除以语速估算的宽松上限，最少 30 秒、最多 300 秒；暂停期间冻结计时。

## 应用与游戏集成

应用启动时加载并初始化语音运行时，不依赖用户访问配置页。初始化失败时禁止正式播报并显示错误，避免用未知默认设置意外发声；配置页可重新加载。保存成功才更新运行时配置，保存失败保持原运行时配置。

问答调用按语义标记场景：题干和答案归 quiz；观众答对归 answer；礼物通关与礼物获得正确答案归 gift；点赞助力归 like；游戏开始/结束归 system。保留游戏自身 voice 开关，它与项目总开关共同控制正式播报。

每题开始清理上一题待播与当前题相关的旧播放；揭晓答案前清理尚未播放的答对/互动反馈，避免过期反馈推迟答案。手动换题、游戏结束或停止时清除该游戏播报，再按配置播报结束消息。只清理游戏所属项目，不影响非游戏系统播报。游戏暂停语音的行为仅在已有明确暂停入口时接入，不新增游戏状态机。

本轮不增加通用欢迎、关注或礼物感谢等新业务事件；场景设置只控制已经接入的问答流程及公共 system 播报。

## 验证与验收

1. 纯函数测试：旧字段迁移、默认深拷贝、非法数字和枚举、场景范围、预设范围、Unicode 截断。
2. Python 临时 SQLite 测试：旧数据库迁移、专用保存往返、非法配置原子拒绝、其他配置保存不覆盖新语音配置。
3. 使用可控浏览器适配器替身测试：音色延迟加载/回退、三种队列模式、优先级与满队列、去重与冷却、禁用、暂停/继续、取消后过期回调、播放失败与超时恢复、试听隔离、按游戏清理。
4. 集成测试：启动加载已保存语音设置，问答场景路由和换题清理，保存失败不更新运行时。
5. 执行现有 Node 测试、Python unittest、TypeScript 类型检查与生产构建。
6. 启动本地开发服务器，使用 Playwright 检查桌面和窄屏截图及操作：音色筛选、参数修改、试听状态、保存、刷新恢复、错误与不支持状态；无横向溢出、文字遮挡、重复提交。
7. 自动化环境若无法验证真实扬声器发声，明确说明；API 调用与模拟状态测试不能代替真实听音验收。

## 实施顺序

先完成兼容配置与专用持久化，再实现可测试的浏览器适配器和队列，随后接入启动与问答场景，最后完成工作台 UI 和浏览器验收。每阶段使用失败测试约束行为，不改动与语音无关的配置和业务。

# 模拟直播脚本演练台设计

## 目标

将当前“固定间隔随机发消息”的模拟直播，重构为可控的脚本演练台，服务三类场景：

- 验收：固定脚本、单步推进、重复复现
- 彩排：按时间轴播放，可暂停、继续、跳过
- 演示：一键运行预置的完整互动流程

## MVP 范围

1. 引入模拟会话状态：`idle / ready / running / paused / finished / error`。
2. 引入脚本事件：`chat / like / gift / join / follow / system`，每个事件包含执行时间、启用状态和 payload。
3. 提供三个模式：
   - `qa`：默认手动推进，适合验收
   - `rehearsal`：按时间轴推进，支持暂停/继续
   - `demo`：加载预置演示脚本，一键播放
4. 控制台增加：
   - 开始、暂停、继续、单步、结束
   - 当前事件与下一事件
   - 手动注入评论、点赞、礼物
   - 脚本事件列表和执行标记
5. 继续复用现有 `interactionRouter`、游戏模块和弹幕展示，不重写游戏规则。
6. 保持跨窗口同步，主控台作为唯一执行源，游戏画面只消费状态。

## 数据流

`SimulationScenario -> SimulationRunner -> DyMessage -> interactionRouter -> game/voice/feed`

模拟执行器负责时间、暂停和游标；事件转换器负责将脚本事件转换为现有 `DyMessage`。手动注入事件直接进入同一转换器和路由链路，保证行为一致。

## 兼容策略

- 保留 `startLiveSimulation` / `stopLiveSimulation` 导出，内部改为驱动新执行器，减少现有调用方改动。
- 旧配置中的时长、观众数和间隔继续可读；没有脚本时自动生成一份兼容脚本。
- 真实直播连接和游戏模块生命周期保持现有约束。

## 验收标准

- 可启动三种模式，状态文案正确。
- 彩排模式可暂停、继续、单步，暂停时不产生新事件。
- 手动评论/点赞/礼物能进入现有弹幕、游戏和语音链路。
- 相同脚本可重复执行，事件顺序和 payload 稳定。
- 结束模拟后能恢复真实直播前状态。
- 现有模拟、弹幕和游戏测试继续通过，并新增执行器与控制动作测试。
